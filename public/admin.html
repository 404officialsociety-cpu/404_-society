Worker API contract

This interface expects these authenticated routes to be implemented in src/worker.js:

  • GET /api/admin/me — verify the signed-in user is an admin
  • GET /api/admin/products — list products and variants
  • POST /api/admin/products — create product
  • PUT /api/admin/products/:id — update product
  • DELETE /api/admin/products/:id — deactivate product
  • GET /api/admin/orders — list orders
  • POST /api/admin/orders/:id/retry — safely retry eligible Qikink fulfillment

Security: Enforce the admin allowlist server-side on every route, validate all input, use parameterized D1 queries, preserve historical order-item snapshots, and make fulfillment retries idempotent. Never expose secrets to browser code.

Database: Apply a versioned D1 migration after backing up the current database. Do not drop the existing orders or customers tables.
